## 已验证

- 在 Windows x64、系统构建号 26200 上，使用 MSVC 19.51、Windows SDK、CMake/Ninja 构建 Release 和 CLion Debug 成功，编译无警告。两个构建的 CTest 均通过。
- CTest **7/7 通过**：状态机/配置测试、直接控制台按键录入、内置资源释放、主程序帮助、检测工具帮助、驱动接口模拟集成、终端配置与错误路径。
- 状态机/配置测试 **1,102 个断言通过**，覆盖抖动、慢移、快速反向、超时、8 kHz 输入序列、实体按键合并、失败清理、扫描码与配置落盘，并验证 F1–F24 和扩展键的名称回显。
- 独立隐藏控制台测试通过 `WriteConsoleInput` / `ReadConsoleInput` 验证 F12、LEFT、F8 捕获和 Enter 确认；Enter 自动重复不跳过下一项，Pause 不绑定，退出后恢复控制台模式。未向真实键盘输入路径注入任何事件。
- 文本/IDE 模式验证名称回显、二次回车确认；输入结束而未确认时不覆盖原配置。
- 将 EXE 单独复制到无 DLL 的目录后，`--check` 成功加载内置 DLL，并到达驱动状态检查。内置 DLL 与安装器均经逐字节释放验证；退出后临时文件和目录删除。
- 模拟驱动集成验证 **19 个输入步骤、16 个输出包**：关闭时透传、长按快捷键只切换一次、清零 X、保留 Y/按钮/滚轮/标记、先释放再反向、停止释放、实体键持有、绝对输入透传、读取失败后释放按键。
- 2026-09-25 过滤器启动修复：本机直接查询 `IOCTL_GET_FILTER` 返回成功但输出长度为 0，官方 DLL 因此返回 0。模拟 DLL 现复现该行为，并检查过滤器仍被设置、退出时被清零；旧版 EXE 在此场景复现 `Cannot enable driver input filters`，修复版完整通过输入包集成测试。Release 和 Debug 的 CTest 均为 **7/7 通过**。
- 本机真实驱动 `--check` 成功枚举 7 个键盘和 4 个鼠标。修复版使用 A/D/F8 配置成功进入 OFF 事件循环，再由独立隐藏控制台的 Ctrl+C 正常退出，打印按键清理信息，退出码 0。此项只验证启动和退出，不构成开启映射后的真实输入效果验证。
- 独立 Raw Input 检测工具可启动并按 `--seconds 1` 正常退出；此次无真实鼠标输入，**不构成屏蔽效果验证**。
- 主程序使用 Windows SDK 系统库和静态 MSVC 运行库；动态加载官方 `interception.dll`，后者依赖系统自带的 `msvcrt.dll` 与 `KERNEL32.dll`。
- 交付目录的 Interception DLL 与固定版本的官方 x64 DLL 的 SHA-256 一致：`ab88164c11b1b48488772d4c3bfaa4509d5b0ae9dbc5a691dc4f96f0260443c8`。
- 附带的上游用户态库源码通过新增的独立 CMake 构建入口编译成功；交付仍使用官方发布 DLL。
